# web

Account dashboard and landing page, deployed for https://relaynet.network as
a Cloudflare Worker with static assets. Static files, no build step. Other
deployments replace `config.js`; `_headers` and `wrangler.jsonc` are
relaynet.network's own (its relay and Auth0 origins, its custom domain).
`index.html` is shared: `app.js` replaces its `wss://relay.relaynet.network`
placeholders (`.relay-ws`) with the configured relay, and shows the support
address and legal links (`data-hosted`) only when `hostedService` is true. The one third-party script is
the OIDC client [oidc-client-ts](https://github.com/authts/oidc-client-ts),
pinned as a devDependency and copied to `public/vendor/` by `npm run vendor`
(deploys and `npm run dev` do it; the copy is gitignored). The page loads only
same-origin scripts (`script-src 'self'`); Dependabot proposes updates.

Sign-in is decided at runtime: OIDC with any provider when `config.js` has an
`oidc` block (relaynet.network: Auth0), and relay accounts (username and
password) when the relay's `GET /api/auth/config` says `passwordLogin`. With
both, the sign-in panel offers both.

The same `GET /api/auth/config` response carries the relay's monthly budget
for the free and anonymous tiers: `budget` (`"open"`, `"throttled"` or
`"paused"`) and `pausedUntil` (`"YYYY-MM-DD"`, the first day of the next UTC
month, or `null`). When `budget` is `"paused"`, `app.js` shows the
`#budget-banner` above the page for signed-in and signed-out visitors alike.

| File | Purpose |
|---|---|
| `index.html` | Landing page (signed out) and dashboard (signed in). |
| `app.js` | Sign-in (OIDC or relay accounts), calls to the relay's `/api/me` and `/api/orgs` routes, rendering: account, usage, sessions, tokens, and organizations (switcher, members, invitations; a `#invite=<token>` link (or the older `?invite=<token>`) is offered after sign-in with Join and Ignore buttons and accepted only on Join; the token is removed from the address bar at once). API data is only ever inserted as text nodes. |
| `config.js` | Public configuration (`window.RELAYNET_CONFIG`): `hostedService` (shows relaynet.network's own text), `relayUrl` (empty: this page's origin) and `oidc` (`issuer`, `clientId`, `audience`, or `null`). Deployments replace this file. |
| `styles.css` | Light and dark themes via CSS tokens. |
| `_headers` | Content Security Policy and other response headers applied to the static assets. |
| `vendor/oidc-client-ts.min.js` | Not in git: copied from `node_modules` by `npm run vendor`. |
| `docs.html`, `docs.md`, `llms.txt` | Generated by `docs/build.py` from `docs/docs.md`; edit that (see [docs/README.md](./docs/README.md)). |
| `terms.html`, `acceptable-use.html`, `privacy.html` | Generated by `infra/legal/build.py` from `infra/legal/*.md`; edit those (see [../infra/legal/README.md](../infra/legal/README.md)). |

## Deploy

Merging a change under `web/` to `main` deploys
(`.github/workflows/deploy-web.yml`, with `cloudflare/wrangler-action`);
`gh workflow run deploy-web.yml` redeploys. After deploying, the workflow
checks that the live `/`, `/app.js`, `/config.js` and vendored script are
byte-identical to the commit, and that the live CSP has `script-src 'self';`.
To see what would be uploaded:

```sh
cd web && npm ci && npm run vendor && npx wrangler deploy --dry-run
```

`wrangler.jsonc` names the Worker, points the assets at `./public` and binds
the apex custom domain `relaynet.network`. The page's origin must stay listed
in `ALLOWED_ORIGINS` in `../relay/fly.toml`.

## Local development

Serve the directory on port 5173 (that origin is allowed in relaynet.network's Auth0 app):

```sh
cd web && npm ci && npm run dev     # copies the SDK, then serves public/
```

`npx wrangler dev` serves it as Cloudflare does, with the `_headers` CSP.

Sign-in works locally, but the relay only accepts browser calls from the
production origin, so the dashboard's data calls return 403 unless
`http://localhost:5173` is added to `ALLOWED_ORIGINS` for a dev relay.

## Connecting

```js
const ws = new WebSocket("wss://relay.relaynet.network", ["relay.v1", "relay.token." + token]);
```

`token` is an API token from the dashboard, a relay-account sign-in token, an OIDC access token with audience
`https://relay.relaynet.network`, or an anonymous token from
`POST https://relay.relaynet.network/api/anon/token` with a `turnstileToken`
in the JSON body.

## Interface

- [docs/README.md](./docs/README.md): the documentation source (`docs/docs.md`)
  and `docs/build.py`, which generates `public/docs.html`, `public/docs.md` and
  `public/llms.txt`.
- `public/`: the static site. It has no README of its own because everything in
  it is deployed. `index.html` loads `config.js`,
  `vendor/oidc-client-ts.min.js`, then `app.js`, all from the same origin.
  - `app.js` is one strict-mode IIFE. It exports nothing and only reads
    `window.RELAYNET_CONFIG` and `window.oidc`. At boot it runs
    `captureInvite`, `initAuth`, `showView`, `loadDashboard`, then `offerInvite`.
  - The relay is `relayBase` (`relayUrl` or `location.origin`). Signed-in
    calls go through `api(path, {method, body})` with `Authorization: Bearer`,
    which sends `X-Relay-Org` only for `/api/me*` paths other than
    `/api/me/orgs` (`orgScoped`). The sign-in calls bypass it:
    `GET /api/auth/config` and `POST /api/auth/login|signup` (`relayAuth`)
    send no token, and `POST /api/auth/logout` is a direct `fetch` with the
    session token.

| Area | Routes called by `app.js` |
|---|---|
| Sign-in | `GET /api/auth/config`, `POST /api/auth/login`, `POST /api/auth/signup`, `POST /api/auth/logout` |
| Account | `GET /api/me`, `DELETE /api/me` (`{confirm}`), `GET /api/me/usage`, `POST /api/me/redeem` (`{code}`) |
| Sessions and tokens | `GET /api/me/sessions`, `DELETE /api/me/sessions/:id`, `GET /api/me/tokens`, `POST /api/me/tokens` (`{name, expiresInDays?}`), `DELETE /api/me/tokens/:id` |
| Organizations | `GET /api/me/orgs`, `GET /api/orgs/:id/members`, `PATCH /api/orgs/:id/members/:user` (`{role}`), `DELETE /api/orgs/:id/members/:user`, `GET /api/orgs/:id/invites`, `POST /api/orgs/:id/invites` (`{email, role}`), `DELETE /api/orgs/:id/invites/:id`, `POST /api/invites/accept` (`{token}`) |

## Invariants

- API data becomes DOM only through text nodes (`el`) or `textContent`.
  `innerHTML` is never used.
- The budget banner's text is built from fixed strings and a date parsed from
  `pausedUntil`, set with `textContent`.
- On an OIDC `?error=` return, only the fixed `SIGN_IN_ERRORS` text is shown,
  never `error_description`.
- `captureInvite` removes the invite token from the address bar at once
  (`history.replaceState`). `takeInvite` makes it single-use. It is accepted
  only on an explicit Join (`invite-join`), never automatically. For accounts
  with `status === "pending"` it is held until the account is activated.
- Sign-in mode: an OIDC manager is created only when `config.oidc` is set and
  `window.oidc.UserManager` is loaded. A saved relay session is used only when
  `GET /api/auth/config` reports `passwordLogin`, and it takes precedence over
  an OIDC user. Sign-up is offered only when `signup` is set, and it requires an
  invite code when `signup === "invite"`.
- `ROLES_CAN` only decides which controls are shown; the relay enforces
  permissions.
- Destructive actions (revoke token, remove member, leave organization, revoke
  invite) need two clicks within 4 seconds. Deleting the account requires
  typing the exact username.
- `_headers`: `script-src 'self'` (no inline scripts or eval), and
  `frame-ancestors 'none'`. `connect-src` and `form-action` list
  only the relay and Auth0 origins. A provider or relay on another origin must
  be added there. `deploy-web.yml` checks that the live CSP has
  `script-src 'self';`.
- `public/docs.html`, `public/docs.md` and `public/llms.txt` are generated.
  CI fails if they differ from `python3 docs/build.py` output.
- Known defect: in `api()`, the destructured `method` (the HTTP verb) shadows
  the outer sign-in `method`. As a result, `res.status === 401 && method ===
  "relay"` never matches, and an expired relay session surfaces as an ordinary
  error instead of `sessionExpiredError()`.

## Side Effects

- Network: `fetch` to `relayBase` only (routes above). OIDC redirects, token
  exchange, silent renewal and sign-out (`signinRedirect`, `signinSilent`,
  `signoutRedirect`) go to `config.oidc.issuer` through oidc-client-ts.
- `sessionStorage`: `relaynet.invite` (pending invite token) and
  `relaynet.session` (`{token, expiresAt, username}`, dropped when expired).
- `localStorage`: `relaynet.org` (selected organization) and the oidc-client-ts
  user store, which holds tokens including the refresh token (`offline_access`).
  Legacy `@@auth0spajs@@*` keys are deleted.
- `history.replaceState` strips invite tokens and OIDC callback parameters.
  `window.location.assign` runs on logout.
- `navigator.clipboard.writeText` copies invite links and new API tokens.
- Deploy: `npm run deploy` (`wrangler deploy`) publishes `public/` to the
  Worker `relaynet` on `relaynet.network`. `npm run vendor` writes
  `public/vendor/`.
